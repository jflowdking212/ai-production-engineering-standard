# APES v1.2.0 — Hermes Orchestration Release

## New

- Central `HermesOrchestrator` for every external AI review call.
- Direct OpenAI and Anthropic provider adapters in addition to OpenRouter and Gemini.
- Auto topology resolution:
  - OpenRouter configured → OpenRouter primary, Gemini fallback;
  - otherwise direct OpenAI/Anthropic → direct primary set, Gemini fallback;
  - otherwise Gemini → immediate Gemini route.
- Capability-aware routing (`medium`, `strong`, `advanced`) so routine work does not automatically consume the strongest model.
- Local response-quality validation integrated into routing; invalid lower-tier output can escalate upward.
- Gemini multi-project credential pool through `GEMINI_API_KEYS_JSON`.
- Model-preserving Gemini rotation: rotate healthy credentials on the selected model before moving to the next model.
- Per-model Gemini 429 cooldown, global credential disable on 401/403, bounded 5xx/network retry, and `Retry-After` support.
- Routing telemetry uses opaque credential ids and never returns API key material.
- Provider/model health state persists across all review chunks within one GitHub job.

## Retained security behavior

- trusted base-branch APES configuration;
- secret preflight/redaction before external providers;
- strict config schema validation;
- complete chunk coverage or fail closed;
- locally validated findings and recomputed verdict;
- P0/P1 merge blocking;
- restricted fork/Dependabot deterministic-only path;
- immutable-style pipeline ref guard.

## Intentional limitation

Hermes health/quota state is currently process-local. Separate workflow runs do not share cooldown knowledge. A future service-mode/Redis state adapter can provide cross-repository persistence without changing the provider interface.
